# 剪金 JianJin

从视频里**快速挑选出有用的片段**并无损导出。

它不是剪辑器：剪辑器假设你已经知道要什么，而剪金假设你还不知道——所以整个界面
为「比实时更快地扫描」而设计，键盘打点，`-c copy` 零重编码导出。

仓库：<https://github.com/hungtcs/JianJin>

## 上手

`⌘/Ctrl+O` 打开视频 → `Space` 播放、`L` 加速扫描 → 看到有用的段落按 `I`/`O`
打点 → `⌘/Ctrl+E` 导出。

## 键盘映射

为单手键盘操作设计，鼠标只用于事后微调。

| 键 | 行为 |
| --- | --- |
| `Space` | 播放 / 暂停 |
| `L` / `J` | 加速 / 减速（1→2→4→8→16x） |
| `K` | 恢复 1x |
| `M` | 静音 / 取消静音 |
| `←` / `→` | ±5s（按住 `Shift` 为 ±30s） |
| `,` / `.` | 逐帧后退 / 前进 |
| `I` / `O` | 标入点 / 标出点 |
| `X` / `Delete` | 删除选中片段 |
| `Esc` | 关闭弹框，或取消未完成的入点 |
| `⌘/Ctrl+Z` | 撤销 |
| `⌘/Ctrl+O` | 打开文件 |
| `⌘/Ctrl+W` | 关闭当前文件 |
| `⌘/Ctrl+E` / `Enter` | 导出 |
| `⌘/Ctrl+,` | 设置 |

标重叠了不必管，片段会自动合并成一段。

## 时间轴

双层结构，共享同一份视图状态。

**细节**（上）—— 可缩放轨，打点时盯的就是它。滚轮平移，`⌘/Ctrl`+滚轮缩放，
触控板双指捏合缩放。刻度尺下方的细刻度是关键帧位置。

**全片**（下）—— 整片地图，**只控制视口，不改播放进度**。绿块是已标片段，
蓝框是上方细节轨正在看的范围：

| 操作 | 行为 |
| --- | --- |
| 拖蓝框主体 | 平移细节轨 |
| 拖蓝框左右边缘 | 缩放细节轨 |
| 点/拖空白处 | 视口居中到指针并跟着拖 |

背景那层很淡的波形用来一眼找出静音段。播放位置是顶边的小三角——这里**不画竖线**：
两轨缩放不同，竖线永远对不齐，反而误导。

### 片段编辑

鼠标移上去光标就会变，不用按下去试：

| 光标 | 位置 | 操作 |
| --- | --- | --- |
| ↔ | 片段边缘 | 拖动调整该端点 |
| ✋ | 片段内部 | 整体平移，**时长不变** |
| ✛ | 空白处 / 刻度尺 | 拖动 scrub |

刻度尺那一条不参与片段交互——它没有绘制片段，就不该能拖动片段。

点击右侧片段列表即**试看**：跳到起点播放，到终点自动暂停。

### 调整高度

播放区与底部之间有一条分隔条，上下拖动可调整时间轴高度。刻度尺与缩略图是固定
高度，**多出来的空间全部归波形**——只有它能从更高的轨道里真正获益。

### 播放跟随

播放时视图自动跟随播放头。**一旦手动平移或缩放，立即交出跟随权**，此后视图纹丝不动，
滚动查看时不会和自动跟随打架。等播放头自己走进当前视野，跟随权无声收回——
此刻视图无需移动，所以不会跳。

## 设置

`⌘/Ctrl+,` 打开。改动即时生效并自动写入配置文件，无需保存：

| 平台 | 配置位置 |
| --- | --- |
| Linux | `$XDG_CONFIG_HOME/jianjin/settings.json`（默认 `~/.config/`） |
| macOS | `~/Library/Application Support/JianJin/settings.json` |
| Windows | `%APPDATA%\JianJin\settings.json` |

**缩略图**与**音频波形**可以单独关闭。它们是打开文件后最昂贵的两项分析——
缩略图要解码全部关键帧，波形要解码整条音轨。素材很大或机器较弱时关掉能立刻
消除卡顿：关闭意味着**完全不启动对应的 ffmpeg 进程**，而不只是不显示。

关闭后对应的带子整条消失、轨道随之变矮，不会留一条空白灰带。若两者都关，
轨道仍保留最小高度，片段与播放头照常可见可拖。

### 外部程序

切割与分析依赖本机的 **ffmpeg / ffprobe**，没有它们就打不开也导不出文件
（播放不受影响——那条路走的是内置解码器）。程序会按「用户指定 → 应用同级目录
→ macOS `.app` 内 `Resources/` → 常见安装路径 → 系统 `PATH`」的顺序查找。

装在非常规位置（解压版、自定义前缀、多版本共存）时，可以在设置的**外部程序**
一节手动指定。这里会如实显示**当前实际会调用哪个文件**及其版本：

- 选中的文件先跑一次 `-version` 验证，跑不起来就不保存，并当场说明原因；
- 指定 ffmpeg 后会顺带认领同目录下的 ffprobe，省一次操作；
- 指定过的路径后来失效（升级、清理）时自动回退到自动查找，并在界面上标出来，
  不会静默失效，也不会因为一次误选就再也找不到。

## 导出

界面右下角切换模式，它直接决定产物时长准不准：

| 模式 | 产物边界 | 速度 | 画质 |
| --- | --- | --- | --- |
| **无损**（默认） | 起点对齐到关键帧，终点精确 | 极快（零重编码） | 不变 |
| **精确** | 与标记完全一致 | 慢 | 重编码，有损 |

### 为什么无损模式起点会偏

`-c copy` 无法从 GOP 中间开始，必须从关键帧起，所以起点会**向前**吸附到最近的
关键帧。偏差等于起点到前一个关键帧的距离，取决于素材的 GOP 长度（录屏常见 2–10 秒）。

**终点不吸附**：解码器读到指定时长就停。向后吸附会白白多包一整个 GOP，
并在末尾留下属于后续内容的关键帧，表现为「结尾画面跳一下」。

### 偏差是可见的

片段列表同时显示标记时长与**实际导出时长**，差额用黄色徽章标出（如 `+2.2s`）。
想消除偏差有两个办法：把入点对到时间轴上画出的关键帧刻度，或切到「精确」模式。

### 不会静默覆盖

目标位置已有同名文件时会先弹框，可选**跳过已存在** / **自动改名**（保留原文件，
新文件加 `-2` 后缀）/ **覆盖**。

## 尚未实现

- 「回补打点」——你常常是在片段*开始之后*才意识到它有用，而 `I`/`O` 要求
  预知起点。固定回溯若干秒是替用户猜，猜不准；连按累加式的回补更合理，待做
- 静音自动分割（`silencedetect`）与镜头切换检测 —— 数据模型已预留
  `SegmentOrigin.silenceGap` / `sceneCut`，产出的「提议」走同一套审核交互
- 导出命名策略（可配置的文件名模板）
- 片段列表持久化 / 工程文件
- smart cut（首尾 GOP 重编码 + 中间 copy 后拼接）—— 可同时拿到「边界精确」
  与「几乎无损」，是现有两档之间理想的第三档
